## Plan mode

Режим **лише для читання**: Claude читає файли, шукає по коду, ставить уточнювальні питання й пропонує план. Редагувань і команд зі змінами стану немає, поки ви не схвалите план — це забезпечує харнес, а не прохання «не пиши код».

- В інтерактивній сесії: **Shift+Tab** циклічно перемикає режими (default → auto-accept edits → plan mode).
- На старті: `claude --permission-mode plan`.

Режим `acceptEdits` застосовує правки файлів без підтвердження кожної; інші дії й далі підпадають під дозволи. Зручно, коли план погоджено, а diff ви переглянете в кінці.

## Коли планувати

План — інструмент проти невизначеності. Багатофайлова міграція (`moment` → `date-fns` у 40 файлах) — так. Одрук у README — ні: попросіть правку й перегляньте diff.

## Цикл

1. **Explore**: «прочитай релевантні файли, код поки не пиши». Назвіть точку входу. Побічні питання доручайте subagents — у головний контекст повернеться лише зведення. Не просіть «прочитати весь репозиторій».
2. **Plan**: попросіть уточнювальні питання — неоднозначність у розмові коштує одне повідомлення, у коді — переробку. Прочитайте план і приберіть зайве (наприклад, непрохане «заодно переписати пагінацію»).
3. **Code**: реалізація за планом.
4. **Verify & commit**: тести й diff, див. [[dev-cc-tdd]] і [[dev-cc-git]].

## План у файлі

Попросіть записати план у `docs/plan-*.md` або GitHub issue. Файл переживе `/clear`, компакцію й нову сесію, стане чеклістом і точкою відновлення. Для 180 помилок лінтера — чекліст у markdown, виправлення по пунктах із позначками.

Якщо посередині з'ясувалося, що план хибний: **Esc**, обговорити факти, оновити файл плану, лише потім продовжити.

## Відкат: checkpoints

Claude Code автоматично зберігає checkpoints правок, зроблених інструментами редагування.

| Інструмент | Для чого |
|---|---|
| Esc Esc / `/rewind` | Повернути розмову та/або код до попередньої точки |
| git | Надійна історія для команди |

Важливе обмеження: **зміни через bash** (`rm`, `mv`, скрипти міграцій) checkpoints не відстежують. Вони локальні для сесії й не замінюють комітів. Зате `/rewind` відкочує лише правки Claude, не зачіпаючи ваших незакомічених змін — на відміну від `git reset --hard`.
