## Що логувати

| Поле | Відповідає на |
|---|---|
| Ідентифікатор запиту (`request-id`, у Python SDK `message._request_id`) | Кореляція з підтримкою Anthropic |
| `usage` з полями кешу | «Чому дорого?» |
| `stop_reason` | «Чому обрізано чи відмовлено?» |
| Виклики інструментів з аргументами й результатами | «Що агент насправді робив?» |
| Версія промпта (`variant`) і моделі | Порівняння версій під flag |
| Тривалість, TTFT | Latency |

**Не логувати:** API-ключі та сирі персональні дані. Метадані — завжди; тексти — лише після маскування і з обмеженим терміном зберігання.

## Трасування агента

Один trace ID на запит користувача, окремий span на кожен виклик моделі й інструмента з `usage`, `stop_reason` і тривалістю. Так видно і зациклення, і найдорожчий крок.

## Метрики, які ловлять тихі регресії

- **Розподіл `stop_reason`**: обрізана відповідь — це HTTP 200 з `max_tokens`, статус-коди її не покажуть.
- **Частка `cache_read_input_tokens`**: падіння до нуля означає зламаний префікс ([[dev-caching-cost]]).
- **Вартість на запит** і частка 429/529.

Алертять на зміну системи й перцентилі, а не на кожен окремий успішний ретрай чи повільний запит.

## Моніторинг якості

Без еталонних відповідей: LLM-суддя з рубрикою на **вибірці** продакшн-трафіку, тренд разом із відгуками користувачів, періодична звірка судді з людьми ([[dev-evals]]).

## Версії моделей

У продакшн-конфігурації фіксуйте датований ідентифікатор (`claude-haiku-4-5-20251001`), а не alias: alias може почати вказувати на новішу версію, і поведінка зміниться без вашого релізу. Перехід на нову модель — свідомий реліз.

## Rollout

1. Offline evals і порівняння з поточною версією.
2. **Shadow mode**: нова версія отримує той самий трафік паралельно, відповіді логуються й оцінюються, користувачі бачать лише стару.
3. **Canary** за feature flag на малий відсоток трафіку.
4. Порівняння якості, вартості, `stop_reason` між групами.
5. Поступове розширення до 100%.

```ts
const variant = flags.get("summary-prompt"); // "v3" | "v4"
const msg = await client.messages.create({ model: MODEL, max_tokens: 1024, system: PROMPTS[variant], messages });
log({ variant, requestId: msg._request_id, usage: msg.usage, stopReason: msg.stop_reason });
```

Якщо canary показує регресію (наприклад, `cache_read_input_tokens` = 0 проти 90% у контролі), вимкніть flag, виправте причину й повторіть. Розширювати canary заради «статистики», коли сигнал однозначний, означає множити шкоду.

## Ретраї

SDK за замовчуванням повторює 408/409/429/5xx з backoff. Власні миттєві цикли поверх них під час 529 множать навантаження. Див. [[dev-api-errors]].
