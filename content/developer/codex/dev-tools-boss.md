## Скелет надійного циклу

```ts
for (let i = 0; i < MAX_ITERATIONS; i++) {
  const res = await client.messages.create({ model, max_tokens, tools, messages });
  messages.push({ role: "assistant", content: res.content });
  if (res.stop_reason !== "tool_use") return handleStop(res); // end_turn, max_tokens, refusal, pause_turn
  const results = await runAllSafely(res.content); // try/catch кожного, is_error
  messages.push({ role: "user", content: results });
}
throw new Error("iteration limit");
```

Порядок ітерації: запит → зберегти `res.content` → розгалузитися за `stop_reason` → виконати всі `tool_use` (небезпечні — після підтвердження) → усі `tool_result` одним повідомленням → лічильник.

⚠️ `if (stop_reason === "end_turn") break` — пастка: на `max_tokens`, `refusal` чи `pause_turn` цикл крутиться далі без результатів.

## Чекліст

| Вимога | Навіщо |
|---|---|
| Ліміт ітерацій + бюджет токенів/часу | Зупинити зациклення й рахунок |
| Детектор однакових викликів | Раннє виявлення петлі |
| `is_error: true` на кожен збій | Модель бачить помилку й виправляється |
| Явна обробка кожного `stop_reason` | Немає «тихих» продовжень |
| Помилка валідації → `tool_result` з текстом | Не підставляти defaults мовчки |
| Невідоме ім'я інструмента → `is_error` зі списком доступних | Сесія не падає |

Зациклення лікують і в інструменті: порожній результат пояснюють («метрики X немає; доступні: …»).

## Контекст

Економте на джерелі: фільтри, glob, ліміт і пагінація в інструменті, обрізання — явне. Довільне видалення старих повідомлень ламає пари `tool_use`/`tool_result`; для цього є context editing і compaction.

## Побічні ефекти

Таймаут ≠ невиконання. Інструменти з побічними ефектами приймають `idempotency_key`: той самий ключ — той самий результат. Надійніше, коли ключ формує код (напр. з `order_id`).

## Безпека

- Результати інструментів (сторінки, документи) — **дані**, а не інструкції; prompt injection там очікувана.
- Мінімальний набір інструментів і прав: `run_sql` — від read-only користувача, з таймаутом і лімітом рядків; запис — вузькими інструментами з підтвердженням.
- Гейт у коді, а не в описі: «ніколи не виконуй DELETE» — лише прохання. Регулярки на фрази чи SQL-слова легко обійти, а `strict` перевіряє форму, а не легітимність.

## Вибір поверхні

Власні інструменти без особливого транспорту — Tool Runner: цикл робить SDK, підтвердження ставлять у функції інструмента або в хуках. Ручний цикл — коли потрібен повний контроль. Власний інструмент не стає server tool.

## Вартість

`tools` і `system` повторюються в кожній ітерації — кешуйте стабільний префікс (детермінований порядок, без змінних даних) і перевіряйте `cache_read_input_tokens`. Не прибирайте `tools` з наступних запитів: API не має стану.
