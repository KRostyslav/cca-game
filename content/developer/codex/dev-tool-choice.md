## Режими `tool_choice`

| Значення | Поведінка |
|---|---|
| `{"type": "auto"}` | Модель вирішує сама — **за замовчуванням** |
| `{"type": "any"}` | Мусить викликати якийсь інструмент, обирає сама |
| `{"type": "tool", "name": "x"}` | Мусить викликати саме `x` |
| `{"type": "none"}` | Не може викликати інструменти |

З `any` і `tool` відповідь одразу починається з `tool_use`, без вступного тексту. З `auto` модель часто пише коротку фразу перед викликами — її лишають в історії як є.

**Коли `any`/`tool`:** маршрутизатор, де кожен клас — інструмент; крок пайплайна, де текст без дії марний; екстракція через інструмент (разом зі `strict: true`).
**Коли `none`:** фінальний підсумок. Краще, ніж видаляти `tools`: префікс не змінюється, кеш цілий.

## Моделі без примусового вибору

Деякі новіші моделі (зокрема `claude-opus-5-5`) повертають 400 на `any` і `tool`. Заміна:

- потрібен лише JSON → `output_config.format` ([[dev-structured-output]]);
- потрібен виклик → `auto` + інструкція в промпті + `strict: true` **і перевірка в коді**, що `tool_use` справді є (інакше повтор або текстова гілка).

Prefill тут не допоможе — на сучасних моделях він теж дає 400.

## `disable_parallel_tool_use`

Поле **всередині** `tool_choice` (не `parallel_tool_calls`):

```json
{ "tool_choice": { "type": "auto", "disable_parallel_tool_use": true } }
```

- з `auto` — не більше одного виклику за відповідь;
- з `any`/`tool` — рівно один.

Вмикайте, коли дії залежні (`reserve_seat` → `charge_card`): модель побачить результат першої, перш ніж просити другу.

## Паралельні виклики

Увімкнені за замовчуванням, beta-заголовок не потрібен. Модель повертає кілька `tool_use` в одному assistant-повідомленні.

1. Додати весь `res.content` в історію.
2. Виконати виклики одночасно, ловлячи помилку **кожного**.
3. Для кожного сформувати `tool_result` з його `tool_use_id`.
4. Покласти всі результати в **одне** user-повідомлення.
5. Надіслати наступний запит.

```ts
const results = await Promise.all(calls.map(async (c) => {
  try {
    return { type: "tool_result" as const, tool_use_id: c.id, content: await runTool(c) };
  } catch (e) {
    return { type: "tool_result" as const, tool_use_id: c.id, content: String(e), is_error: true };
  }
}));
```

Голий `Promise.all` без try/catch відхиляється на першій помилці, і жоден результат не повертається.

## Пастка «по одному»

Якщо розкладати результати по окремих user-повідомленнях, API не скаржиться, але історія вчить модель робити виклики по одному — агент повільнішає. Усі результати однієї відповіді — разом.
