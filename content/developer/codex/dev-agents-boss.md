## Чеклист готовності

| Що | Навіщо |
|---|---|
| `maxTurns` + обробка `error_max_turns` | Межа вартості й зациклення |
| Логи `session_id`, `total_cost_usd`, `num_turns` з `result` | Спостережуваність кожного запуску |
| Перевірка `mcp_servers` в `init` | Падати голосно, якщо сервер не `connected` |
| Контрактні тести MCP-сервера в CI | Контракт інструментів не ламається непомітно |
| Логи сервера в stderr | stdout — канал протоколу |
| Явні `allowedTools` + `canUseTool` замість `bypassPermissions` | Контроль там, де його ніхто не дублює |

## Сервер не під'єднався

Якщо `init` показує `status: "failed"`, модель просто не має інструментів, і промпт чи дозволи цього не змінять. Відтворіть команду сервера в контейнері: шлях, runtime, змінні середовища.

## Дозволи з людиною в циклі

Читальні інструменти (`mcp__tickets__get_ticket`) — в `allowedTools`, небезпечні (`close_ticket`) — через `canUseTool`, що чекає рішення людини. `disallowedTools` заборонить назавжди, а `PostToolUse` спрацює запізно. Субагенту-рецензенту звужуйте `tools` у визначенні, бо без цього поля він успадкує все.

## Секрети й tenant-и

```ts
mcpServers: { crm: { type: "http", url, headers: { Authorization: `Bearer ${process.env.CRM_TOKEN}` } } }
```

Секрет живе на рівні транспорту: модель його не бачить, у контекст і `tool_use` він не потрапляє. У мультитенантному сервері tenant визначається з перевіреного токена, а аргументи моделі — недовірений ввід.

## Архітектура

- **In-process** (`createSdkMcpServer`) підходить для одного агента. Якщо інструмент потрібен кільком клієнтам, винесіть його в окремий MCP-сервер.
- **stdio** означає процес на кожного клієнта. 20 реплік дають 20 пулів з'єднань без спільного rate limit. Спільний ресурс краще віддати окремим сервісом на Streamable HTTP (`type: "http"`).
- **Сесії** SDK лежать на локальному диску процесу. У stateless-контейнерах `resume` не спрацює без постійного тому, прив'язки до інстансу або власного зберігання історії.

## Якість інструментів

- Порожній «[]» провокує десятки повторних пошуків. Повертайте, що шукали, які є фільтри і як розширити запит. `maxTurns` лишається страховкою.
- Допустимі значення задавайте через `z.enum` у схемі, помилку — з переліком значень. Правило в промпті застаріє.

## Розслідування збою

1. За `session_id` з логів знайти запуск і виклик, що впав, з аргументами.
2. Відтворити виклик в MCP Inspector.
3. Написати контрактний тест, що падає.
4. Виправити зі збереженням сумісності й задеплоїти.
5. Прогнати eval агента на відповідних сценаріях.
