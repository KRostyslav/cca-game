## Старт

Запускайте `claude` з **кореня репозиторію**: цей каталог стає робочим каталогом сесії, звідти підтягується проєктний CLAUDE.md. Далі — `/init`: Claude аналізує кодову базу й пише **чернетку** CLAUDE.md з командами збірки, тестів і помітними домовленостями. Перечитайте її, доповніть неочевидним і закомітьте. Першою дайте невелику задачу: вона покаже, чи пам'яті вистачає.

Якщо Claude повторює ту саму помилку (наприклад, запускає тести не тією командою), виправте це в пам'яті через `/memory`, а не нагадуванням у кожному запиті.

## Як Claude бачить репозиторій

Індексу немає. Автоматично на старті завантажується лише CLAUDE.md, а файли Claude шукає й читає інструментами (Grep, Glob, Read) на вимогу. Додатковий каталог підключають через `/add-dir ../shared-lib` або `--add-dir`.

## Способи дати контекст

| Спосіб | Приклад |
|---|---|
| Згадка файлу | `Поясни @src/auth/session.ts` |
| Bash-режим | `! npm run lint` — вивід іде в розмову без участі моделі |
| Зображення | вставити скриншот чи перетягнути файл |
| stdin | `cat build-error.log \| claude -p "Знайди причину"` |

`claude -p` — одноразовий неінтерактивний запит: вхід зі stdin, відповідь у stdout, дозволи діють як завжди. Докладніше в [[dev-cc-automation]].

Для UI найкраща специфікація — скриншот: «скриншот → правка → новий скриншот».

## Конкретність запиту

Погано: «Додай тести для `foo.py`». Добре: «Напиши тест для `foo.py` на випадок, коли користувач не залогінений; без моків». Файл, сценарій, обмеження — і менше вгадувань.

## Керування сесією

| Дія | Що робить |
|---|---|
| Esc | Перериває поточну дію, контекст зберігається |
| Esc Esc | Повернення до попереднього повідомлення, щоб змінити запит |
| `/clear` | Скидає розмову; CLAUDE.md завантажиться знову |
| `/compact` | Стискає історію |
| `/context` | Показує, чим зайняте контекстне вікно |
| `/doctor` | Діагностика встановлення й автооновлення |

Коригуйте курс **одразу**: якщо Claude пішов редагувати не той модуль, Esc і уточнення дешевші за відкат готових змін. Між незалежними задачами робіть `/clear`: зайвий контекст відволікає й коштує токенів у кожному запиті, а все важливе вже живе в CLAUDE.md і git.

Наступний крок — планування великих змін: [[dev-cc-plan-mode]].
