## Один оборот

1. Клієнт надсилає запит із `tools` і повідомленням користувача.
2. Модель повертає блок `tool_use` і `stop_reason: "tool_use"`.
3. **Ваш код** виконує функцію з `input`.
4. Клієнт надсилає всю історію плюс `tool_result` з тим самим `tool_use_id`.
5. Модель відповідає зі `stop_reason: "end_turn"` (або просить ще виклики).

API не має стану: `tools` і повна історія йдуть у кожному запиті.

## Ручний цикл

```ts
messages.push({ role: "assistant", content: res.content }); // весь content!
if (res.stop_reason !== "tool_use") { /* end_turn, max_tokens, refusal... */ }
messages.push({
  role: "user",
  content: [{ type: "tool_result", tool_use_id: block.id, content: JSON.stringify(out) }],
});
```

## Правила, що дають 400

| Помилка | Чому |
|---|---|
| В історію додано лише текст відповіді | `tool_result` посилається на `tool_use`, якого немає |
| Результат лише для першого з кількох `tool_use` | Кожен `tool_use` потребує свого `tool_result` у наступному повідомленні |
| Текст стоїть перед `tool_result` | Блоки `tool_result` мають іти першими в `content` |
| Роль `tool` | Такої ролі немає — лише `user` |

`tool_use_id` — це `id` блоку `tool_use` (`toolu_...`), а не ім'я інструмента чи id повідомлення.

## Що може бути в `content`

Рядок (зокрема серіалізований JSON) або масив блоків `text`, `image`, `document`. Сирий об'єкт без серіалізації — ні.

## Помилки й великі результати

- Збій інструмента → `tool_result` з `is_error: true` і зрозумілим описом. Не виходьте з циклу і не пропускайте результат.
- Порожній результат пояснюйте: «0 результатів для X; спробуйте ширший запит».
- Великий вивід — фільтри, пагінація, а обрізання **явно** позначене в результаті.

## Stop reasons і запобіжники

- `max_tokens` з обрізаним `tool_use` — **не** виконувати; повторити з більшим `max_tokens` (великі значення — через streaming).
- Ліміт ітерацій і детектор однакових викликів обов'язкові.
- З `eager_input_streaming: true` API не буферизує і не валідує вхід: збирайте `input_json_delta`, перевіряйте за схемою і лише тоді виконуйте.

## Підтвердження людиною

Модель лише **просить** виклик. Гейт для небезпечних дій ставлять у коді перед виконанням; відмову повертають як `tool_result` («користувач відхилив»), щоб модель могла відреагувати. Опис «завжди питай дозволу» — лише прохання.

## Tool Runner

`client.beta.messages.tool_runner(...)` (Python) / `toolRunner` (TS) крутить цикл за вас: викликає API, виконує ваші функції локально, додає `tool_result` і повторює, доки модель не перестане викликати інструменти. Це не Agent SDK і не server tools. Паралельні виклики — у [[dev-tool-choice]].
