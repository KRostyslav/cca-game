## Гілка на старті

Claude Code не створює гілок сам — він працює з репозиторієм у тому стані, який є. Перед фічею попросіть створити `feature/...` або зробіть це самі. Гілка ізолює зміни й дає просту точку відкату.

## Коміти

Просячи «закоміть з осмисленим повідомленням», ви отримуєте повідомлення на основі `git status`, `git diff` і стилю з `git log`. Хороше повідомлення описує **поведінку і причину**, а не перелік файлів:

```
fix(payments): не списувати двічі при повторі запиту — перевірка idempotency key
```

Правила гігієни:

- переглядайте `git diff` **до** коміту — звіт Claude не замінює погляду на зміни;
- комітьте після кожного логічного кроку з зеленими тестами;
- не дозволяйте сліпого `git add -A`: так потрапляють `.env`, логи, тимчасові скрипти;
- `.env` у локальному коміті: `git rm --cached .env`, `git commit --amend`, додати в `.gitignore`. Якщо секрет уже запушено — відкликати й перевипустити.

Один PR — одна мета. Якщо форматер переформатував 30 сторонніх файлів, відкотіть їх або винесіть в окремий коміт чи PR.

## Дозволи для git

```json
{
  "permissions": {
    "allow": ["Bash(git status)", "Bash(git diff:*)"],
    "ask": ["Bash(git push:*)"]
  }
}
```

Читальні команди — вільно, дії за межами машини — з підтвердженням. Детальніше про правила — стаття Architect-треку про дозволи.

Замість `git push --force` після rebase — `--force-with-lease`: він відмовить, якщо віддалена гілка змінилася після вашого fetch. Переписувати історію спільних гілок чи `main` — рішення команди, не агента.

## PR через `gh`

Встановлений і автентифікований `gh` дає Claude `gh pr create`, `gh pr view`, `gh issue view`. Коментарі рев'юера до PR #248 Claude прочитає через `gh`, виправить код і запушить у ту саму гілку — обговорення збережеться.

Опис PR будують за `git diff main...HEAD`: три крапки беруть merge-base, тож у diff лише зміни гілки, без нових комітів `main`.

## Історія й конфлікти

- «Чому тут три ретраї?» — `git log -S`, `git blame`, пов'язані PR. Факти замість здогадок.
- Конфлікт rebase — це злиття **намірів**: з'ясувати, що змінила кожна сторона, об'єднати в одну логіку, прогнати тести. «Завжди ours/theirs» губить одну зі змін.

Мердж PR і переписування спільної історії лишаються за людьми.

## Паралельні сесії: worktrees

```bash
git worktree add ../shop-search -b feature/search
cd ../shop-search && claude
```

Дві сесії в одному каталозі перезаписують файли одна одної, перемикання гілок міняє файли під ногами. Worktree — окремий робочий каталог на своїй гілці зі спільною історією. Про масштабне застосування — [[dev-cc-boss]].
