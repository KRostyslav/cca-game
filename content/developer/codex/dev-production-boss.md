## Порядок етапів

1. **Eval-набір на реальних даних** і базова метрика. П'ять вибраних прикладів з демо — не метрика ([[dev-evals]]).
2. **Оптимізація вартості** — кешування, батчі — з повторним прогоном eval ([[dev-caching-cost]], [[dev-batch-latency]]).
3. **Безпековий огляд**: дозволи інструментів, недовірені дані, секрети ([[dev-security]]).
4. **Canary за feature flag** з моніторингом якості, вартості й `stop_reason` ([[dev-observability]]).
5. **Повний реліз** після стабільних метрик.

Оптимізувати вартість до появи eval передчасно: ви не помітите, якщо оптимізація зіпсує якість.

## Типові пастки й лікування

| Симптом | Хибне рішення | Правильне |
|---|---|---|
| `cache_read_input_tokens` = 0 при 30k-токенному промпті | `ttl: "1h"`, дроблення блоків | Прибрати дані клієнта з початку промпта |
| Нічна обробка 200k записів ловить 429 і заважає вдень | Більше паралельності, без ретраїв | Message Batches API з `custom_id` |
| Ін'єкція в тікеті викликала `issue_refund` на 2000 | Попередження в промпті, фільтр слів | Поріг у коді інструмента + підтвердження людини |
| Нова модель краща в середньому, але гірша в критичній категорії | Реліз з дисклеймером | Блокувати, виправити, викотити через flag з метриками за категоріями |
| 8% відповідей з `stop_reason: "max_tokens"` | Автопродовження другим запитом | Підняти `max_tokens`, обробляти в UI, алерт на частку |
| 529 `overloaded_error` у піку | Миттєві повтори ×10 | Backoff з jitter, обмежені спроби, деградація для користувача |

## Кешування: стабільне попереду

```ts
const system = [
  { type: "text", text: KNOWLEDGE_BASE, cache_control: { type: "ephemeral" } },
  { type: "text", text: `Клієнт: ${customer.name}, план: ${customer.plan}` },
];
```

## Чеклист перед релізом

- [ ] Eval проганяється на кожну зміну промпта чи моделі, з порогами для критичних категорій.
- [ ] Логуються `usage`, `stop_reason`, ідентифікатор запиту, версія промпта й моделі.
- [ ] Feature flag для миттєвого вимкнення й відкату.
- [ ] Ретраї SDK увімкнені; побічні ефекти захищені ідемпотентністю, а не відмовою від ретраїв.
- [ ] Бізнес-пороги й підтвердження незворотних дій — у коді.
- [ ] API-ключ лише на сервері й ніколи в логах.
- [ ] Модель зафіксована датованим ідентифікатором.

Реліз без спостережуваності, кнопки відкату й регресійних тестів — експеримент на користувачах.
