## Етапи

1. **Страховка**: гілка, зафіксований зелений прогін тестів (базова лінія), характеризаційні тести на слабо покриті критичні шляхи. CI не вимикати, `bypassPermissions` не вмикати.
2. **Мапа**: у [[dev-cc-plan-mode]] дослідити використання, зокрема subagents по пакетах; скласти мапу впливу й поетапний план у файлі.
3. **Механіка**: codemod на AST (`ts-morph`, `jscodeshift`), який пише Claude; прогнати, переглянути diff.
4. **Ручні випадки**: по пакетах, коміт на кожен етап.
5. **Фінал**: повний набір тестів і type-check усього репо, рев'ю diff-а, PR.

## Codemod замість 300 правок

Однакову механічну зміну детермінований скрипт робить однаково, його можна перезапустити й переглянути. Редагувати кожен файл окремо — повільно, дорого й неоднорідно; глобальний `sed` без AST зачепить рядки й коментарі.

## Довга задача і контекст

Стан живе в **git і файлі плану**, не в розмові. Після етапу: коміт → позначка в плані → `/clear` → наступний етап із плану. Автокомпакція стискає історію з втратами, тож обмеження на кшталт «не змінювати публічний API `@acme/sdk`» тримають у CLAUDE.md і плані, а критичні ще й технічно.

## Технічні межі

Якщо Claude чіпає `dist/` чи `package-lock.json`, прохання «будь уважнішим» не допоможе, а `.gitignore` не заборонить редагування. Потрібні правила `deny` для Edit/Write або `PreToolUse`-hook ([[dev-cc-automation]]); CLAUDE.md пояснює причину.

## Паралелізм

Незалежні пакети — окремі git worktrees і гілки, своя сесія в кожному, потім злиття з повним прогоном. Кілька сесій в одному каталозі заважатимуть одна одній. Див. [[dev-cc-git]].

## Коли щось пішло не так

- **Упали «непов'язані» тести** — порівняти з базовою лінією. Падали й раніше — стара проблема; нові — модулі насправді пов'язані, і це знахідка для плану. Не латати наосліп і не вимикати.
- **План неповний** (виклики через рядкові ключі, яких codemod не бачить) — зупинитися, оновити план, знайти всі входження пошуком, додати перевірку на старе ім'я (grep у CI чи тест), потім продовжити. Тимчасовий аліас — лише з планом видалення.

## Рев'ю і злиття

| Тип змін | Як перевіряти |
|---|---|
| Механічні (codemod) | окремий PR чи коміт, скрипт + вибірка |
| Логічні | людське рев'ю рядок за рядком |
| Усе разом | повні тести й type-check, незалежна сесія чи subagent зі свіжим контекстом |

Самозвіт «усе зроблено, тести зелені» — не доказ. Тести лише змінених файлів недостатні: рефакторинг API ламає саме викликачів у незмінених файлах. Див. також [[dev-cc-tdd]].
