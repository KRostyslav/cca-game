## Коди помилок

| Код | Тип | Повторювати? |
|---|---|---|
| 400 | `invalid_request_error` | Ні — виправити запит |
| 401 | `authentication_error` | Ні — ключ відсутній, невалідний чи відкликаний |
| 403 | `permission_error` | Ні — налаштування доступу |
| 404 | `not_found_error` | Ні — помилка в id моделі або модель недоступна організації (`GET /v1/models`) |
| 413 | `request_too_large` | Ні — зменшити тіло, великі файли через Files API |
| 429 | `rate_limit_error` | Так — ваші ліміти, дивитися `retry-after` |
| 500 | `api_error` | Так |
| 529 | `overloaded_error` | Так — перевантаження сервісу для всіх |

Плюс мережеві збої й таймаути — теж тимчасові. Повтор детермінованого 400 лише додає затримку.

## Політика повторів

1. Перехопити помилку й визначити тип.
2. Перевірити, чи вона тимчасова.
3. Пауза: `retry-after`, а без нього — експоненційний backoff з **jitter**, щоб клієнти не повторювали синхронно («thundering herd»).
4. Повторити, рахуючи спроби.
5. Після ліміту — помилка або деградація: запасна модель, черга, зрозуміле повідомлення.

`max_retries=50` — погана ідея: з backoff це хвилини очікування й додаткове навантаження під час збою.

## Rate limits

Ліміти діють на рівні організації: запити, вхідні й вихідні токени за хвилину. Інший ключ тієї ж організації не допоможе. Заголовки `anthropic-ratelimit-*` показують залишок і час скидання — за ними гальмують ще до 429.

## SDK

SDK сам повторює 408, 409, 429, 5xx і мережеві помилки; за замовчуванням 2 рази.

```python
client = anthropic.Anthropic(max_retries=5)
client.with_options(max_retries=1).messages.create(...)

try:
    msg = client.messages.create(**params)
except anthropic.RateLimitError:      # спершу специфічні
    schedule_retry(params)
except anthropic.APIStatusError as e:  # потім базовий
    log.error("api error %s", e.status_code)
```

Базовий клас, поставлений першим, перехоплює всі підкласи. Не порівнюйте тексти повідомлень. Мережеві збої — `APIConnectionError`, `APITimeoutError`.

**Таймаути:** у Python — секунди, у TypeScript — **мілісекунди** (`timeout: 60` = 60 мс). Таймаути теж повторюються, тож загальний час може сягати `timeout × (max_retries + 1)`; довгі генерації переводять на streaming ([[dev-api-streaming]]).

**Streaming:** повтори SDK стосуються встановлення запиту. Помилка посеред потоку піднімається у ваш код — рішення з частковим виводом ухвалюєте ви.

## `request-id`

Кожна відповідь має заголовок `request-id` (у SDK — `_request_id`). Логуйте його разом з `usage` і `stop_reason`: саме за ним підтримка знайде запит. API-ключ не логують.

## Ідемпотентність

Генерація не має зовнішніх побічних ефектів — повтор коштує лише токенів. Небезпечне повторне виконання **ваших** дій: списання грошей, email, записи в БД. Інструменти роблять ідемпотентними ключем, похідним від `tool_use_id` чи id замовлення, і перевіркою «вже виконано».
