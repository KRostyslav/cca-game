## Головний принцип

**Guardrail — технічний, а не текстовий.** Код, дозволи й підтвердження працюють незалежно від того, що «вирішила» модель. Промпт і few-shot лише змінюють імовірність.

| Механізм | Guardrail? |
|---|---|
| Allowlist інструментів для агента | ✓ |
| Перевірка аргументів у коді інструмента | ✓ |
| Підтвердження людини перед незворотною дією | ✓ |
| Речення в системному промпті чи CLAUDE.md | ✗ вплив |
| Few-shot з відмовою | ✗ |

## Prompt injection

Непряма ін'єкція приходить з даних: листів, сторінок, тікетів, результатів інструментів. Шари захисту від найнадійнішого:

1. Небезпечної дії **немає** в дозволах агента.
2. Підтвердження людиною перед незворотною дією.
3. Розмітка недовірених даних тегами (`<document>…</document>`) — допомагає, але не гарантує.
4. Інструкція ігнорувати вказівки з даних.
5. ✗ Фільтр ключових слів — обходиться перефразуванням.

Агент, що читає недовірений вміст, не повинен мати `send_email`, запису в БД чи доступу до секретів. Витік вимагає одночасно недовіреного вводу, чутливих даних і каналу назовні: розірвіть будь-яку ланку — розділіть агентів, обмежте веб-інструменти `allowed_domains`, не кладіть у контекст зайвого.

## `tool_use.input` — недовірені дані

```python
def issue_refund(inp: dict) -> str:
    amount = float(inp["amount"])
    if amount > 50:
        return request_human_approval(inp)
    ...
```

- Пороги й бізнес-правила — у коді, не в промпті й не в `input_schema`.
- SQL-інструмент працює під обліковим записом **лише з читанням** потрібних таблиць, а не через адмінське з'єднання.

## Вивід моделі — теж недовірений

Відповідь, на яку вплинули зовнішні дані, може містити `<img onerror=...>`. Не вставляйте її через `innerHTML`: рендерте як текст або санітизуйте HTML/Markdown.

## Секрети

- API-ключ — лише на сервері: змінна середовища чи менеджер секретів. Не у фронтенді (мініфікація не ховає рядки) і не в `localStorage`.
- Жодних паролів і рядків підключення в промпті: модель може їх процитувати. Облікові дані тримає код інструмента.
- Ключ потрапив у публічний репозиторій — **спершу відкликати** в Console й випустити новий, перевірити використання, потім чистити історію git.

## Claude Code

Заборона читати секрети в репо — правила `deny`, а не прохання в CLAUDE.md:

```json
{ "permissions": { "deny": ["Read(./.env)", "Read(./secrets/**)"] } }
```

`.gitignore` на доступ до файлів не впливає. Детальніше про дозволи агентів — [[dev-agent-sdk-tools]].
