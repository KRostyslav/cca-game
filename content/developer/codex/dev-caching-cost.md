## Як працює

Кешування — **побайтовий збіг префікса** в порядку `tools` → `system` → `messages`. Точка `cache_control` кешує весь префікс до цього блоку включно. Зміна будь-якого байта раніше знецінює все, що після неї. Кешується вхід, а не відповідь моделі.

```ts
await client.messages.create({
  model: MODEL,
  max_tokens: 1024,
  system: [
    { type: "text", text: KNOWLEDGE_BASE, cache_control: { type: "ephemeral" } },
    { type: "text", text: `Клієнт: ${customer.name}` }, // змінне — після точки
  ],
  messages,
});
```

- До **4 точок** `cache_control` на запит.
- Префікс, коротший за мінімум для моделі, **тихо не кешується** — без помилки, `cache_creation_input_tokens: 0`.
- Beta-заголовок не потрібен.

## TTL

| Варіант | Запис | Коли |
|---|---|---|
| За замовчуванням, 5 хв | ≈1.25× від вхідного | Запити частіше ніж раз на 5 хв |
| `ttl: "1h"` | ≈2× | Інтервали 5–60 хв |

Читання коштує ≈0.1× і **оновлює** таймер. Якщо запити приходять раз на 10 хвилин, 5-хвилинний запис щоразу встигає зникнути.

## Агентний цикл

Історія агента лише дописується. Точка в кінці розмови (або top-level автоматичне кешування `cache_control` на запиті) дає інкрементальне кешування: кожен хід платить повну ціну лише за нове.

## Тихі інвалідатори

| Причина | Лікування |
|---|---|
| `datetime.now()` на початку `system` | Винести після точки |
| Ім'я чи план клієнта на початку | Змінне — після стабільного |
| Новий чи змінений інструмент | Стабільний набір `tools` |
| Порядок інструментів з `Map`/плагінів | Сортувати за `name` |

Довжина **не** інвалідатор: великий стабільний префікс дає найбільшу економію.

## Облік: поля `usage`

- `input_tokens` — некешований вхід;
- `cache_creation_input_tokens` — записано в кеш;
- `cache_read_input_tokens` — прочитано з кешу;
- `output_tokens` — вивід.

Полів на кшталт `cache_hit_ratio` немає: частку влучань рахуйте самі. Стабільний нуль у `cache_read_input_tokens` — шукайте інвалідатор.

## Підрахунок токенів

Endpoint `count_tokens` (`client.messages.countTokens` у TS) приймає ті самі `model`, `system`, `messages`, `tools` і повертає `input_tokens` без генерації. Ділити символи на 4 чи брати чужий токенізатор неточно.

## Порядок зниження вартості

1. Гігієна входу: інструменти повертають лише потрібні поля.
2. Кешування стабільного префікса.
3. [[dev-batch-latency]] для нетермінових масових задач.
4. Лише потім компроміси: слабша модель, нижчий effort — після перевірки на [[dev-evals]].

Занизький `max_tokens` — хибна економія: обрізана відповідь означає повторний запит.
