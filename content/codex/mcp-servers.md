## Конфігурація в Claude Code

| Область | Де |
|---|---|
| Проєкт (комітиться, спільна для команди) | `.mcp.json` у корені репозиторію |
| Особиста / користувацька | `claude mcp add` у відповідній області видимості |

## MCP-конектор у Messages API

Потрібні **обидві половини**:

```json
{
  "mcp_servers": [
    { "type": "url", "url": "https://mcp.example.com", "name": "docs" }
  ],
  "tools": [
    { "type": "mcp_toolset", "mcp_server_name": "docs" }
  ]
}
```

Тільки `mcp_servers` без `mcp_toolset` → помилка валідації. Потрібен beta-заголовок `mcp-client-2025-11-20`.

## Дизайн сервера

Для бази знань на тисячі документів:

- ✓ інструмент пошуку з фільтрами, що повертає короткі фрагменти;
- ✓ інструмент отримання повного документа за ідентифікатором;
- ✗ один інструмент «повернути все»;
- ✗ по інструменту на кожну категорію — десятки схожих визначень роздувають контекст.

Патерн «пошук + деталізація» дає just-in-time контекст ([[retrieval-context]]).

## Безпека стороннього сервера

Підключення чужого MCP-сервера — це одночасно:

1. **Код у вашому середовищі.** Протокол не є пісочницею: локальний сервер працює з правами процесу, що його запустив. Він може писати, видаляти й ходити в зовнішні API.
2. **Текст у вашому контексті.** Описи його інструментів впливають на поведінку моделі й можуть спонукати до дій, яких ви не планували.

Тому підключення сервера варто розглядати і як зміну коду, і як зміну промпта — з відповідним обмеженням дозволів ([[guardrails]]).

## Занадто багато інструментів

Симптоми: повільний старт, неправильний вибір, роздутий контекст. Лікування — консолідація схожих операцій плюс `defer_loading` для рідкісних. Розділення на кілька серверів не допомагає, якщо підключені всі.
