## Файли налаштувань

| Файл | Область |
|---|---|
| Керовані корпоративні налаштування | Уся організація, найвищий пріоритет |
| `.claude/settings.json` | Проєкт, комітиться в репозиторій |
| `.claude/settings.local.json` | Особисті налаштування в цьому проєкті, не комітяться |
| `~/.claude/settings.json` | Усі проєкти цього користувача |

## Пріоритет

Керовані корпоративні налаштування перекривають локальні. Усередині будь-якого рівня **`deny` сильніше за `allow`**. Конфлікт правил — штатна ситуація, що розв'язується пріоритетом, а не помилкою.

## Три категорії дозволів

```json
{
  "permissions": {
    "allow": ["Bash(npm run test:*)", "Read(./src/**)"],
    "ask": ["Bash(curl:*)"],
    "deny": ["Read(./.env)", "Read(./secrets/**)"]
  }
}
```

- `allow` — рутина без запитань;
- `ask` — «можна, але під наглядом»;
- `deny` — жорсткий бар'єр.

## Правила пишуть за префіксом

| Правило | Покриває |
|---|---|
| `Bash(npm run test:*)` | `npm run test`, `npm run test:unit`, `npm run test:e2e` |
| `Bash(npm:*)` | Усе npm, включно з `publish` — зазвичай завужче не потрібно |
| `Bash(npm run test)` | Лише точний збіг — не покриє `test:unit` |

Принцип найменших привілеїв: правило має покривати потрібне і не більше.

## Settings vs CLAUDE.md

Розмежування просте:

- **`settings.json`** — те, що виконує харнес: дозволи, hooks, змінні середовища.
- **`CLAUDE.md`** — те, що читає модель: пояснення, домовленості, контекст.

Правило стилю в `settings.json` не побачить ніхто; дозвіл у CLAUDE.md не застосує ніхто.
