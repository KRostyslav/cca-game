## Схема як обмеження

- `enum` замість вільного рядка там, де множина значень скінченна;
- `required` для обов'язкових полів;
- `additionalProperties: false` для закритої схеми;
- осмислені описи полів.

Нормалізація «кривих» значень на боці інструмента приховує помилку: невідоме значення тихо перетвориться на щось інше.

## strict: true

Гарантує, що `tool_use.input` точно відповідатиме схемі. Це поле **самого інструмента**, поруч із `name`, `description`, `input_schema` — не всередині `tool_choice`. Вимагає `additionalProperties: false` і `required`.

Несумісний із programmatic tool calling.

## Структуровані помилки

```json
{
  "error": "not_found",
  "message": "Користувача з id 4821 не знайдено.",
  "hint": "Скористайтеся search_users за email або іменем, щоб отримати коректний id."
}
```

Код дає машинну однозначність, повідомлення — контекст, підказка — шлях уперед. Такий формат перетворює збій на самовиправлення.

Чого не робити:

- ✗ кидати виняток і переривати цикл — модель не побачить помилки;
- ✗ повертати порожній об'єкт — не відрізнити «не знайдено» від «не спрацювало»;
- ✗ повертати `"Error"` без деталей.

На рівні API помилка повертається тим самим каналом, що й успіх: `tool_result` із тим самим `tool_use_id` і `is_error: true`.

## Обсяг виводу

Двоступенева видача — типовий патерн:

1. Пошук повертає короткі записи з ідентифікаторами, з лімітом за замовчуванням і пагінацією.
2. Окремий інструмент дістає повний запис за id.

Будь-яке обрізання має бути **явним у відповіді**, інакше модель робитиме висновки на неповних даних як на повних.

## Ідемпотентність

Ретрай неминучий: таймаути трапляються, відповіді губляться. Інструмент із побічними ефектами має приймати ключ ідемпотентності й повертати наявний результат для вже обробленого ключа.

Це властивість інструмента, а не дисципліни викликача.
