## Headless-запуск

```bash
claude -p "Перевір діф на регресії" \
  --output-format json \
  --allowedTools "Read,Grep,Bash(npm run test:*)" \
  --max-turns 15
```

- `-p` — одноразовий неінтерактивний запит;
- `--output-format json` — машинозчитуваний вивід для наступних кроків пайплайну;
- `--allowedTools` — явний allowlist;
- `--max-turns` — обов'язковий у CI ліміт.

## Головне правило

**Дозволи в автоматиці мають бути вужчими за локальні, а не ширшими.** В інтерактивній сесії є запобіжник — людина. У CI його немає.

`bypassPermissions` у CI — антипатерн: раннер має доступ до токенів і мережі.

## Недовірений вхід

Вміст пул-реквесту від зовнішнього контриб'ютора — це **недовірені дані**. Агент рев'ю потребує лише читання й пошуку, тож саме цим набір інструментів і має обмежуватися. Запис у гілку чужого PR — і ризик безпеки, і зміна чужого коду без згоди.

## Чекліст CI

- [ ] Ключ API — у секретах CI, не в репозиторії.
- [ ] Явний allowlist інструментів.
- [ ] Ліміт ходів і контроль вартості запусків.
- [ ] Спільна конфігурація — у `.claude/settings.json` (не `settings.local.json`, він особистий).
- [ ] Hooks увімкнені: у CI вони дають детерміновані перевірки без людини.

## Обмеження обсягу змін

Для джобів на кшталт «онови залежності й створи PR» межі задають технічно: дозволи визначають, куди взагалі можна писати, hook на `PreToolUse` ловить решту. Промпт задає намір, дозволи — периметр.
