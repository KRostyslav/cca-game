## Чотири підходи

Два незалежні питання: **хто дає харнес** (цикл + керування контекстом) і **хто дає деплой**.

| Підхід | Ви пишете | Харнес і деплой | Інструменти |
|---|---|---|---|
| Messages API, ручний цикл | Весь цикл | Ваші обидва | Лише ваші |
| Tool Runner (`client.beta.messages.tool_runner`) | Лише функції інструментів | SDK дає цикл; хостинг ваш | Лише ваші |
| **Managed Agents** | Конфіг агента | Anthropic дає **обидва** | Пісочниця + Skills/MCP + ваші |
| **Claude Agent SDK** | Промпт + опції | SDK дає харнес Claude Code; хостинг ваш | Вбудовані Read/Write/Edit/Bash/Glob/Grep/Web* + MCP + subagents |

## Що таке Claude Agent SDK

Це **Claude Code, упакований у бібліотеку** (`claude-agent-sdk` / `@anthropic-ai/claude-agent-sdk`). З коробки:

- вбудовані інструменти файлової системи, пошуку та bash;
- система дозволів і hooks;
- субагенти й сесії;
- підтримка MCP-серверів;
- керування контекстом.

Чого він **не** дає — деплою. Сервер, масштабування, моніторинг лишаються вашими.

## Agent SDK ≠ Tool Runner

Обидва — harness only, але різного обсягу:

- **Tool Runner** — тонкий цикл над інструментами, які ви визначили самі. Жодних вбудованих інструментів.
- **Agent SDK** — повний харнес Claude Code з готовим набором інструментів.

## Як обрати

| Обмеження | Вибір |
|---|---|
| Дані не залишають периметр | Agent SDK у власній інфраструктурі |
| Потрібен розклад, керований стан, робоча область без свого сервера | Managed Agents |
| Кілька власних інструментів, свій цикл не потрібен | Tool Runner |
| Потрібен нестандартний контроль потоку | Ручний цикл |

## Обмеження прав

Набір доступних інструментів задається конфігурацією, а не проханням у промпті. Це технічний контроль — його не обійти вмовляннями. Див. [[guardrails]].
